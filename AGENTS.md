# AGENTS.md: working on it-intelligence

This is the contract for agents (Claude Code, Codex, Cursor) and people. `BRIEF.md` holds the design and
the reasons; this file holds the rules.

## The order of things

1. **The ontology comes first.** `ontology/*.yaml` (LinkML) declares every entity kind and relation kind.
   `make ontology` generates the store vocabulary, Go and TypeScript types, JSON Schema, OWL, SHACL and
   docs. Never edit `ontology/generated/`, `store/vocabulary.sql` or `web/lib/generated/` by hand; CI fails
   if they differ from what `make ontology` produces. A new kind or relation needs an entry in
   `ontology/CHANGELOG.md` naming the question it lets someone answer, and the owner's agreement.
2. **Connectors know nothing about the ontology.** They read and emit observations. Company conventions
   (label names, naming patterns) live in `mapping/` and `config/mapping.yaml`.
3. **Observations are append-only.** The model is a pure function of the latest observations, the stored
   judgements and the decision log (`resolver.Build`). If a fact is wrong, fix the source, the mapper or a
   rule, never a row.
4. **Every relationship has a basis, a confidence and a source.** No inferred link becomes asserted without
   a person (`ConfirmLink`). Rejections stick until the evidence changes.
5. **One query layer.** REST and MCP are adapters over `api/query`. A new question goes there first, then
   into both surfaces; `api/parity_test.go` checks they agree.

## Checks before you say done

```sh
make dev-db && make dev-ingest     # PostgreSQL on :55432, the seed ingested
make test                          # with ITX_TEST_DATABASE_URL=postgres://itx:itx@localhost:55432/itx for the DB tests
make dev-verify                    # resolver against seed/truth.yaml, the article's claims against the system
cd web && npx tsc --noEmit         # the UI still compiles against the ontology
```

`itx verify` must pass. If a change moves a number the article quotes (a confidence, a score, a path),
say so: the article and the code are kept in step.

## Changing the seed

`seed/` is generated by `seed/gen` (`make seed-gen`) and committed. Change the generator, never the files.
The generator refuses to write a truth model with problems nobody planted; every planted problem is in
`planted()` and must be found by an insight.

## Writing

Plain, calm English. No em or en dashes. The Kestrel Group is fictional: never use a real company's
name, products, internal tools or conventions in code, data or docs.

## Ask the owner before

Changing the licence, renaming the repository, adding a dependency outside Apache-2.0, MIT, BSD, ISC or
MPL-2.0, adding an entity or relation kind, pushing to a public remote, or tagging a release.
